## Task 1 — the record grows a parallel meta tuple

`src/ash_captions/app/transcript.py`.

* `WordStyle` is imported from `ash_captions.styles.schema` when that module
  has it (track B/F add it) and otherwise defined here with exactly the
  fields the Interfaces section fixes: `colour`, `scale`, `bold`, `italic`,
  `x`, `y`, all optional. The guarded import is the same "works against an
  older module" idiom `runner_util.accepted_kwargs` already uses, and it
  means the two tracks converge on one class the moment B merges.
* `WordMeta(edited, retimed, break_before, no_break_before, style)`, frozen,
  every field defaulted, so `WordMeta()` is "nothing was done to this word".
* `TranscriptRecord` gains `meta: tuple[WordMeta, ...] | None = None` and
  `revision: int = 0`. One validator — `__post_init__` — raises `ValueError`
  when `meta` is present and `len(meta) != len(words)`, so a record with a
  drifted meta tuple cannot be constructed at all, in any code path,
  including `dataclasses.replace`.
* `FORMAT_VERSION = 2`, `SUPPORTED_FORMATS = (1, 2)`. A version-1 file loads
  to `meta=None, revision=0`; a version-2 file with `"meta": null` is the
  same thing. Only non-default keys are written per meta entry, and `meta`
  is written as `null` when every entry is default, so a freshly transcribed
  job's file is the v1 file plus `"revision": 0` and two nulls.

**Tests** (`tests/test_app/test_transcript_edits.py`):
a v1 file on disk loads with `meta is None` and `revision == 0`; a round trip
of a record with meta and styles is exact; a mismatched meta length raises;
`save_transcript` of an untouched record writes `"meta": null`.

## Task 2 — the five operations

Same file, pure functions, each taking a record and returning a new one with
`revision + 1`. None of them do I/O.

* `set_text(record, index, text, *, all_occurrences=False)` — replaces the
  word's text, sets `edited=True` and **drops the confidence to 0.0**: a
  hand-typed word has no model confidence. `all_occurrences` changes every
  word whose *core* (the text with leading/trailing punctuation stripped)
  matches case-insensitively, preserving each occurrence's own capitalisation
  (`Haramienta` → `Herramienta`, `HARAMIENTA` → `HERRAMIENTA`) and its own
  surrounding punctuation (`haramienta,` → `herramienta,`). `occurrences()`
  is exported as its own pure function so the popup's count and the edit
  itself can never disagree.
  A source-text edit also sets `extra["en_stale"] = True`; `en_words` is left
  exactly as it was.
* `retime(record, index, *, start=None, end=None)` — the moved edge is
  clamped to the neighbour on that side and then to a 60 ms minimum
  duration; when the neighbours leave less than 60 ms, the neighbour clamp
  wins. Sets `retimed=True`.
* `split(record, index)` — word `index` must start a new caption line
  (`break_before=True`, `no_break_before=False`).
* `merge(record, index)` — word `index` must **not** start a new line, i.e.
  it joins the line above (`no_break_before=True`, `break_before=False`).
  The UI's "merge with the next line" passes the first word of that next
  line, which is the same thing said from the other end.
* `set_style(record, index, style)` — `style` is a dict validated here
  (`parse_word_style`) or `None` to clear. Validation is this track's: hex
  colour, scale 0.5–3.0, booleans, `x`/`y` fractions in [0, 1], no unknown
  keys. What the renderer does with it is track B's.

`set_text` and `retime` also resync `record.segments`, so the `.txt` written
from segment text carries the edit: the matching word inside each segment
(matched on its original `(start, end)`) is replaced, and the segment's
`text` is rebuilt from the joined words when it was the join of those words
to begin with — postprocessing that rewrote a segment's text in a way words
alone cannot reproduce leaves that text alone rather than corrupting it.

**Tests**: one per operation, plus — confidence dropped on edit; `all`
preserves capitalisation and punctuation; `all` count matches `occurrences`;
retime clamped by both neighbours and by the 60 ms floor; a style survives a
split; an unknown style key is rejected; `en_stale` set by a text edit and
not by a retime; every operation bumps the revision by one; segments carry
the new spelling.

## Task 3 — `build_cards` learns about forced breaks

`src/ash_captions/engine/rules.py`.

```python
@dataclass(frozen=True, slots=True)
class CardBreaks:
    before: frozenset[int] = frozenset()      # must start a new card
    not_before: frozenset[int] = frozenset()  # must not
```

`build_cards(..., breaks: CardBreaks | None = None)` forwards it to
`_group_words`, which is restructured minimally: the "should break" decision
already made after appending a word becomes a `pending_break` flag consulted
before the *next* word, so `not_before` can veto it and `before` can force
one. The trailing short-group fold does not fold a group whose first word
carries a `before` marker. Nothing else changes — no new grouping rule, no
change to silence dropping, gap snapping or the minimum-duration floor.

**Tests** (`tests/test_engine/test_rules_breaks.py`): the same word lists the
existing `test_rules.py` uses, built with `breaks=None` and with
`CardBreaks()`, are identical to `build_cards` without the parameter at all;
a `before` marker starts a card mid-phrase; a `not_before` marker joins two
cards the max-words rule would have split; a marker cannot produce a card
that loses or reorders words (every word appears exactly once, in order).
The existing `tests/test_engine/test_rules.py` is the byte-identity proof and
must pass untouched.

## Task 4 — the helpers the renderer path needs

`src/ash_captions/app/runner_util.py`.

* `word_style_map(record) -> dict[tuple[float, float], WordStyle]` — every
  word carrying a style, keyed by its `(start, end)`, exactly as the
  Interfaces section fixes. `{}` for a record with no meta.
* `card_breaks(record) -> CardBreaks | None` — `None` when no word carries a
  marker, so the no-markers path is provably the old path.
* `rewrite_outputs(record, *, output_dir, stem, preset, position, play_res)`
  — build cards with the markers, then atomically rewrite `<stem>.ass`,
  `<stem>.srt` and `<stem>.txt`; returns the card count. `word_styles` is
  passed to `engine.write_ass` only when that function accepts it
  (`accepted_kwargs`, the module's existing probe), so this works today and
  picks up track B's renderer the moment it merges, with no edit here.
  `.en.srt` is not touched: `en_words` is not edited by this track.

**Tests** (`tests/test_app/test_runner_util_edits.py`): the map is keyed by
timings and skips styleless words; `card_breaks` is `None` for a clean
record; `rewrite_outputs` writes all three files and the `.srt` carries the
edited spelling and the forced line break; a `word_styles` keyword is passed
when the renderer accepts one and silently skipped when it does not.

## Task 5 — the API

`src/ash_captions/web/routes_transcript.py`. The existing GET grows the new
fields (additive — `studio_check.js` keeps working unchanged).

**`GET /api/jobs/{id}/transcript`** now returns
`{language, revision, en_stale, words:[{w,s,e,p,edited,retimed,break_before,no_break_before,style}], en_words}`.

**`PATCH /api/jobs/{id}/transcript`**

```json
{"revision": 3, "ops": [{"op": "set_text", "index": 12, "text": "herramienta", "all": false}]}
```

Ops: `set_text` (`index`, `text`, `all`), `retime` (`index`, `start?`,
`end?`), `split` (`index`), `merge` (`index`), `set_style` (`index`,
`style` object or `null`). Applied in order to one in-memory record and
saved once — a bad op anywhere means nothing is written. On success the
record is saved with `revision + n`, the outputs are rewritten through
`runner_util.rewrite_outputs`, and the response is the whole new transcript
plus `cards`. A `revision` that is not the record's is **409** carrying
`detail` (a sentence for the toast) *and* `transcript` (the current record),
so the other tab reloads instead of clobbering. 404 without a transcript,
409 for an unreadable one and for a bad index or value.

**`POST /api/jobs/{id}/glossary`** — `{"from": "haramienta", "to":
"herramienta"}` appends `haramienta => herramienta` to the job's client
glossary, or to the shared `glossary.txt` when the job has no client. The
client path goes through the injected `ClientGlossaryProvider.write_glossary`
— the same call `PUT /api/clients/{c}/glossary` makes, so the same
`validate_glossary_text` rules and the same 400. The shared path validates
with that same function and writes with the same temp-and-replace. An
identical line already present is not appended twice.

The glossary provider is read off `request.app.state.glossary_provider`
inside this module rather than being passed into `build_transcript_router`,
so `web/app.py` needs no edit and no other track's merge collides with it.

**Tests** (`tests/test_web/test_transcript_edit_api.py`): one per op through
the real route; the stale-revision 409 carries the current record; a bad
index is 409 and leaves the file untouched; the `.srt`/`.txt`/`.ass` on disk
carry the edit; the PATCH needs `X-ASH-Client` like every other mutation;
glossary POST writes the line for a client job and to the shared file for a
client-less one; a duplicate line is not appended; `from`/`to` with a `=>`
or a newline in it is a 400.

## Task 6 — the panel

`src/ash_captions/web/static/studio_edit.js` + `studio_edit.css`, mounted in
a new empty `#transcript-edit` element.

The lines shown are the ones the server actually wrote: the panel parses the
job's `.srt` and assigns words to cues, the way `studio_check.js` does, so
"this line is too long" is about a real line and not a guess. After every
PATCH the `.srt` is re-fetched and the panel re-rendered.

* Click a word → popup with the word in a text field and, side by side:
  **Fix this one**, **Fix every "haramienta" (4)** — the count from the same
  `occurrences` rule the server uses — and **Always spell it this way**
  (the glossary POST). Below: **Split line here** on a word that is not the

* Drag a word's left or right edge: a grip on each side, 1 s per 200 px,
  live readout, clamped by the neighbours and 60 ms, committed on release as
  one `retime`.
* A line longer than the current look's `max_words` (read from
  `GET /api/styles`) shows a quiet warning on that line.
* An edited word shows a small pencil mark; a retimed one a small clock.
* `window.AshStudioEdit` exposes `onWordEdited(index)` (call it to tell the

`studio.html` gains exactly two lines: `<div id="transcript-edit"></div>`

## Known deviations from the spec, decided up front

1. **The mount element is `#transcript-edit`, not `#transcript`.** The
   Interfaces table names `#transcript`, but `studio.js` owns that element
   (`loadTranscript()` fills it with a chip strip whenever
   `AshStudioCheck` is absent). A new empty element is the contract the
   rest of the section actually asks for and cannot collide with a file
   this track may not edit.
2. **`merge(index)` means "this word does not start a line".** The spec's op
   list gives `{"op": "merge", "index": 12}` without saying which side; this
   is the reading that makes `split` and `merge` exact opposites on the same
   index, which is what `build_cards` needs.
3. **`WordStyle` is defined defensively in `app/transcript.py`** until
   `styles/schema.py` has it (tracks B and F own that file).
4. **`CardBreaks` is not re-exported from `engine/__init__.py`** — that file
   is not this track's.

## Found while building, for the integrator

- **Two transcript panels are on screen at once.** `studio_check.js` (v0.5)
  already renders the source words in `#check`, and this track's panel
  renders them again, editable, in `#transcript-edit` above it. Both work
  and neither breaks the other, but the Studio now says the same words
  twice. The fix is one line in `studio.js` — stop calling
  `AshStudioCheck.mount` and fold the English row and the "N uncertain
  words" chip into this panel — and `studio.js` is not this track's file.
- **`QueueAdapter.restyle` does not yet know about the markers or the
  per-word styles.** It calls `engine.build_cards` without `breaks` and
  `engine.write_ass` without `word_styles`, so picking a look after an edit
  rebuilds the `.ass` with the look's own line breaks. `runner_util.
  rewrite_outputs` is the one call that does it correctly; `adapter.py`
  (not this track's) should call it. The same is true of the burn path in
  `runner.py`.
- **A job whose footage is gone gets no editing panel**, because
  `studio.js` only fires `onReady` once a video is playing. The caption
  check has the same limit today.

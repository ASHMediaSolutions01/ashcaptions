# v0.6 track B — Style one word

Plan for section 2 of `docs/superpowers/specs/2026-09-05-v0.6-design.md`.
Branch `v06-B-word-style`, worktree `.claude/worktrees/v06-B-word-style`.
Five other tracks build in parallel; the spec's Interfaces section is the
contract.

Goal: an editor selects one word and gives it its own colour, size, weight
or slant, without leaving the Studio and without changing the look. Font
family and outline stay properties of the look — that boundary is the
design, not an omission.

## The seam

`styles/render.py:_line_text` already wraps every word in its own `{...}`
override block. The whole engine change is: emit the look's tags first and
the word's own tags last inside that same block, so the word wins, and
close what was opened so the words after it are untouched.

`render.py` is 491 lines and must stay under 500, so all of the per-word
merge logic lives in a new `styles/render_word.py`; `render.py` only
threads `word_styles` through and calls it.

**Amended while building.** Threading the keyword through four builders
still pushed `render.py` to 571 lines, so `render.py`'s whole "per-word
text and inline effect tags" section — `_escape_ass_text`,
`_prepare_word_text`, `_line_text`, `_active_word_tags`, `_pop_scale_tags`
— moved into `render_word.py` too, public-named, which is where the
per-word merge happens anyway. `render.py` ends at 469 lines. That move
needed `POP_HALF_MS` and `scale_transform_tags`, so those moved from
`render_glow.py` into `render_word.py` and `render_glow` re-exports them
(it imports this module, never the other way round); its own tests name
them from `render_glow` and are untouched.

## Tasks

### 1. `WordStyle` in `styles/schema.py`

Exactly the Interfaces shape: `colour`, `scale`, `bold`, `italic`, `x`,
`y`, all `None` by default, a frozen slots dataclass like every other
model in that module. `x`/`y` are track F's free placement — declared here
so F builds on a field that exists, ignored by this track's renderer.

`from_dict` validates the way the rest of the module does: `colour`
through the existing `_require_hex_colour`, `scale` through
`_require_number` bounded by the module's existing `_MIN_SCALE`/`_MAX_SCALE`
(0.5–3.0), `bold`/`italic` through `_require_bool`, `x`/`y` through
`_require_number` bounded 0.0–1.0, unknown keys rejected by
`_reject_unknown_keys`. `to_dict` drops `None` fields so a round-trip
through the transcript record stays small. Added in its own region at the
end of the sub-models block, so track F's `Layout.mode` change never
touches the same lines.

**Test** — `tests/test_styles/test_word_style.py`: every field
round-trips; a bad hex, a scale of 0.4 and of 3.1, a non-bool `bold`, an
out-of-range `x` and an unknown key each raise `StyleValidationError`
naming the field; `WordStyle()` is all-`None` and `to_dict()` is `{}`.

### 2. `render_word.py` — the merge

New module, importing only `ass_format`, `schema` and `render_glow`, so
there is no cycle with `render`.

- `word_style_for(word, word_styles)` — looks a word up by its
  `(start, end)` key; `None` when the mapping is empty or absent.
- `scale_pct(ws)` — the word's own scale as an integer percentage, `100`
  when unset.
- `scaled_transform_tags(scale, base_pct)` — the pop `\t` chain rebuilt
  around a base other than 100: `\fscx{base}\fscy{base}`, up to
  `base * scale`, back to `base`. This is how a word given 1.25 in a `pop`
  look pops *from* 1.25 instead of having its pop replaced.
- `override_tags(ws, *, restore_colour=None, include_scale=True)` — the
  word's own tags and the tags that put the line back afterwards: `\c`
  (plus `\c{restore}` on close), `\b1`/`\b0`, `\i1`/`\i0`, and
  `\fscx/\fscy` when the caller has not already baked the scale into a
  `\t` chain. Returns `("", "")` for `ws is None`, which is what keeps the
  output byte-identical.
- `karaoke_override_tags(ws, style)` — the same, but setting `\c` *and*
  `\2c` so the word reads as its colour in both halves of a `\kf` sweep.

**Test** — `tests/test_styles/test_render_word.py`: each helper as a pure
function, including `override_tags(None) == ("", "")` and the base-100
case of `scaled_transform_tags` agreeing with `scale_transform_tags`.

### 3. `render.py` — thread `word_styles` through

`render_ass(cards, style, *, play_res=None, anchor=None, word_styles=None)`
where `word_styles` is `Mapping[tuple[float, float], WordStyle]`.
`write_ass` gains the same keyword. `_card_events` gains the parameter and
passes it to all three builders.

- `_line_text` (pop, none, shake, card_box, and glow's text layer): the
  word's override appended inside the existing brace pair; the close block
  only emitted when there is something to close, so a word with no
  override still renders `{\c&H..&}word` with no trailing block.
- `_active_word_tags` gains an optional `ws`: for `pop`/`glow` the scale
  composes through `scaled_transform_tags`; for `shake`/`none` the
  override carries a plain `\fscx/\fscy`.
- `_box_events`: one word per event in the `_BOX` style. `_pop_scale_tags`
  changes to return its tags *without* the surrounding braces so the scale
  transform and the word's override share one block; the call site wraps
  it, so a card with no override emits the identical string.
- `_karaoke_events`: the override goes into the same block as `\kf`, and a
  close block restores the look's colours before the next word.

**Tests** — `tests/test_styles/test_render_word_styles.py`: colour, scale,
bold and italic each on their own; scale composing with the active-word
pop (the peak is `base * pop`, not `pop`); an override on a non-active
word; a word in a `box`, a `scale_box`, a `karaoke` and a `card_box` look;
a key matching no word ignored.

### 4. Byte-identical output

`word_styles=None` and `word_styles={}` must render exactly today's `.ass`.
The existing goldens in `tests/test_styles/golden/` are the proof and are
not touched.

**Test** — in `test_render_word_styles.py`: for every golden fixture
style, `render_ass(cards, style)` equals `render_ass(cards, style,
word_styles={})` equals `render_ass(cards, style, word_styles=<no-match>)`.
`test_render_golden.py` passing unchanged is the other half.

### 5. The glow halo

The halo layer must keep the same text metrics as the text layer or the
halo drifts off its word, so `render_glow.halo_line_text` gains an optional
per-word style list and applies bold, italic and scale to *every* word on
the halo line (including the transparent ones) and the colour override to
the active word's `\3c`, which is the halo's own colour. Default `None`
renders byte-identically.

**Test** — a glow look with a coloured, scaled word emits the override
colour as `\3c` on layer 0 and the same `\fsc` values on both layers.

### 6. A real-libass pixel test

`tests/test_styles/test_word_style_real.py`, modelled on
`test_glow_real.py` and skipped unless `ASH_REAL_FFMPEG` is set: a two-word
card in a plain look, the second word given `#FFD166`, burned onto flat
grey by the bundled ffmpeg. The left half of the frame has white pixels and
no amber; the right half has amber pixels.

### 7. `studio_word.js` / `studio_word.css`

New files publishing `window.AshStudioWord` with `select(index)` and
`clear()`, mounting into a new empty `#word-toolbar`.

- Pure helpers first, exported for node the way `studio_check.js` does:
  `effectiveStyle(word, look)` (what the look already gives this word, so
  every control is pre-filled and the toolbar reads as a diff),
  `hasOverride(word)`, `styleFromControls(...)`, `patchBody(revision,
  index, style)` building the documented op shape, `resetAllOps(words)`.
- The panel: a scope line — "Changing **this word** only." with a link to
  change the look instead — above colour, size (a percentage), bold and
  italic; then **Reset word** and **Reset all overrides on this job**.
- Opens from a click on the caption on the video, and from a click on a
  word in the transcript. **Amended while building:** the transcript path
  works today without track A — a capture-phase listener picks up any
  element carrying `data-word-index` (A's panel, when it lands) and falls
  back to the caption-check panel's own spans, which are already in
  transcript order. The capture phase is what gets past `studio_check.js`
  stopping the click after it seeks. The video path is a click on
  `studio_drag`'s caption handle that did not move: the caption is a
  canvas, so the word it can name is the one at the playhead.
- A word carrying an override gets a dot, in the transcript and on the
  toolbar's own label.
- Persists through `PATCH /api/jobs/{id}/transcript` with
  `{"revision": n, "ops": [{"op": "set_style", "index": i, "style": {...} |
  null}]}` — track A's route. No route is added here.
- The stylesheet is injected by the script itself rather than adding a
  third line to `studio.html`, keeping this track's edit there to the two
  lines it owns.

**Test** — `tests/test_web/test_studio_word.py`, node-driven like
`test_studio_check.py`: the pure helpers and the `patchBody` shape; plus a
fake-`fetch` test that selecting a word, changing its colour and saving
issues exactly one PATCH with the documented body, that **Reset word**
sends `"style": null`, and that a stale-revision 409 does not clobber.

# v0.6 Track C: Export everywhere, named honestly — Implementation Plan

**Goal:** Every finished job's files are real browser downloads, from three
places (Studio header, every finished queue row, the Styles page), and the
word "export" means exactly one thing: the finished burned-in video.

**Architecture:** One new route, `GET /api/jobs/{id}/files/{name}`, serves a
named output as an attachment — the name is matched against the existing
`GET /api/jobs/{id}/files` listing, never joined onto a path. One new
self-contained front-end module, `export.js`, publishes `window.AshExport`
with `mount(jobId, container)` (a `container` argument beyond the documented
`mount(jobId)`, defaulting to `#export`, so the same component can also drop
itself into a queue row's actions cell — see Task 3's note on why this is
backward compatible with the documented one-arg call). It fetches the file
listing, offers a download per category (video, `.srt`, `.ass`, `.txt`,
`.en.srt` when present), and — when the burned video is missing — offers to
queue it and polls the new job until it is done, wording the control so
walking away is clearly safe.

**Spec:** `docs/superpowers/specs/2026-09-05-v0.6-design.md`, section 3 and
the Interfaces section (the `#export` / `AshExport` row).

## Global constraints

- Every source file stays under 500 lines
  (`tests/test_web/test_studio.py::TestPage::test_web_files_stay_under_500_lines`
  globs `web/*.py` and `static/*.js`/`*.css`, so it covers the new files too).
- `GET` routes are exempt from `ClientOriginMiddleware` (`web/security.py`
  only guards mutating methods), so the new download route needs no header
  checks of its own — same as `/files`, `/video`, `/ass` and the font-file
  route today. "Same checks as every other route" means: none beyond what
  every other `GET` route already gets for free.
- Name matching follows the exact pattern already shipped for
  `GET /api/fonts/file/{filename}` (`routes_studio.py`): look the name up in
  a listing built from `Path.iterdir()`, never `output_dir / name`. A name
  that isn't in the listing is a 404, whatever it looks like — `..`, an
  absolute path, or a name with no file behind it, are all just "not a
  match," so no separate traversal-detection code is needed.
- Run tests with `.venv\Scripts\python.exe -m pytest tests -q` from the
  worktree root; `ruff check src tests scripts` must be clean too.
- Run from `C:/Users/mbila/Desktop/ASH Captions/.venv/Scripts/python.exe` —
  never `pip install -e .` (repoints the shared venv for every other agent).

### Task 1: `GET /api/jobs/{id}/files/{name}`

**Files:** modify `src/ash_captions/web/routes_review.py`; modify
`tests/test_web/test_review.py`.

**Behaviour:** Look `name` up in `_scan_outputs(output_dir)`. No match (job
not found, no output dir, name not present, or a traversal attempt that
therefore never appears in the listing) is a 404. A match is served as a
`FileResponse` with `content_disposition_type="attachment"` (the
`FileResponse` default — no override needed, unlike the `inline` routes
above it) and a media type from an extension map covering `.mp4`, `.srt`,
`.ass`, `.txt` (falling back to `application/octet-stream`).

- [ ] Add the route, reusing `job_or_404`, `output_dir_of`, `_scan_outputs`.
- [ ] Tests in `test_review.py::TestDownload`:
  - `test_downloads_a_listed_file` — content matches bytes on disk, content-type, `content-disposition` starts with `attachment` and carries the filename.
  - `test_downloads_the_captioned_video_with_video_media_type`
  - `test_unknown_job_is_404`
  - `test_name_not_in_the_listing_is_404` — a file that exists on disk under a *different* job's folder, requested by this job's id, proves the match is against *this* job's own listing, not any file that happens to exist.

### Task 2: `export.js` / `export.css`

**Files:** create `src/ash_captions/web/static/export.js`,
`src/ash_captions/web/static/export.css`.

**Behaviour:**
- `mount(jobId, container)`: `container` defaults to
  `document.getElementById("export")`. Renders a small "Export ▾" control.
  Each `mount()` call is an independent instance — the queue page mounts one
  per finished row, all sharing the one loaded script.
- Loads the job (`GET /api/jobs/{id}`) and its outputs
  (`GET /api/jobs/{id}/files`). While the job isn't `done` yet, polls every
  2s rather than rendering an empty menu (the Studio's `#export` can be
  present on a still-running job).
- Categorizes outputs: captioned video (prefers `*.captioned.mp4`, falls
  back to any other `.mp4`, mirroring `_burned_output` in
  `routes_studio.py`), source-language `.srt` (excludes `.en.srt`, mirroring
  `_transcript_srt`), `.ass`, `.txt`, and `.en.srt` (omitted entirely when
  absent — not everyone runs the translate pass).
- Every present file is a real `<a download href="/api/jobs/{id}/files/{name}">`
  with its size formatted (`B`/`KB`/`MB`/`GB`).
- Missing video: checks `GET /api/jobs` for a `pending`/`running` job whose
  `output_dir` matches this job's (i.e. a burn already queued for it, found
  after a page reload) before offering a fresh "Queue the burn" button —
  this is what makes "you can navigate away" actually true across a
  reload, not just within one page view.
- Clicking "Queue the burn" posts `{preset: job.options.preset}` to
  `POST /api/jobs/{id}/burn`, then polls the returned job id every 1.5s.
  While pending/running: a progress bar plus "Exporting… still running if
  you leave this page." On done: re-fetches `/files` and swaps in the real
  download link. On failure: a toast (`AshToast`, already loaded on every
  page that will load this script) and reverts to the button.
- No new API surface: everything above calls only existing routes
  (`GET /api/jobs/{id}`, `GET /api/jobs`, `GET /api/jobs/{id}/files`,
  `POST /api/jobs/{id}/burn`) plus the one route Task 1 adds.

**Tests:** no JS test runner exists in this repo yet (checked: no
`package.json`, no `*.test.js`); introducing one is out of this track's
scope. Correctness for the pure categorization rules is covered indirectly
by exercising the same fixtures Task 1's route tests use and reasoning from
the mirrored Python logic; a manual live check (download each file type
from a real browser, queue a burn, confirm it survives a navigate-away) is
called out in the report as unverified by an automated test, matching how
the design spec treats "live checks" as the integrator's job after all
tracks land.

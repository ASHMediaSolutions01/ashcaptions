## What "free mode" is

A look in `mode: "free"` stops laying words out as a line. It carries a
list of **slots** — each a position on the frame, a size multiplier, a
colour role, an italic flag, an optional font and an entrance. The
renderer emits **one Dialogue event per word**, each pinned to its slot
with `\pos`, each **ending when the card ends** rather than when the next
word starts, so words accumulate on screen instead of replacing each
other. Which word lands in which slot is decided by a pure function of
the card's own words.

`mode` defaults to `"line"`, so all 36 shipped looks render byte-identical
`.ass` to today. The golden files in `tests/test_styles/golden/` are the
proof and are not regenerated.

### 1. Schema: `Layout.mode` and `Layout.slots`

`src/ash_captions/styles/schema.py`, in one region at the end of the
sub-models, above `Layout`.

New enums:

- `LAYOUT_MODES = {"line", "free"}`
- `SLOT_COLOUR_ROLES = {"text", "active", "outline", "shadow", "box"}` —
  a role names a key of the look's own `colors` block, so a slot never
  carries a raw hex colour and a palette change moves every slot with it.
- `FREE_ENTRANCES = {"none", "stretch_collapse", "fade_settle"}`

New frozen dataclass `Slot`, validated exactly like the rest of the
module (a message naming the field at fault):

| field | type | default | range |
|---|---|---|---|
| `x` | float | required | 0.0–1.0, fraction of frame width |
| `y` | float | required | 0.0–1.0, fraction of frame height |
| `scale` | float | 1.0 | 0.2–3.0, multiplier on the look's `size` |
| `role` | str | `"text"` | one of `SLOT_COLOUR_ROLES` |
| `italic` | bool | false | |
| `font` | str \| None | None | a bundled family; None = the look's font |
| `entrance` | str | `"stretch_collapse"` | one of `FREE_ENTRANCES` |

`Layout` gains `mode: str = "line"` and `slots: tuple[Slot, ...] = ()`.

Boundary rules, all raising `StyleValidationError`:

- `mode: "free"` with an empty `slots` list is rejected.
- `mode: "line"` with a non-empty `slots` list is rejected (a slot list
  that never renders is a mistake, not a no-op).
- in free mode `len(slots) >= max_words`, so a card can never overflow
  its slots and stack two words on one point.
- at most 8 slots (`max_words`'s own ceiling).

`Layout.from_dict` takes a keyword-only `check_font: bool = True`,
threaded from `Style.from_dict`, so the per-slot font is validated against
the bundled manifest by exactly the same rule as `Style.font` and the
`check_font=False` test path still works.

`Style.to_dict()` grows a `Layout.to_dict()` so `slots` round-trips as a
list of plain dicts rather than dataclasses (the style editor and the web
layer both serialise it as JSON).

**Test** — `tests/test_styles/test_free_schema.py`: defaults are
`line`/`()`; a full free layout parses; each field's out-of-range,
wrong-type and unknown-value rejection names its own path
(`layout.slots[1].scale`, ...); free-with-no-slots, line-with-slots and
`slots < max_words` all rejected; an unbundled slot font rejected and
accepted under `check_font=False`; `to_dict` → `from_dict` round-trip is
an identity; a `Layout` with no `mode`/`slots` key is unchanged.

### 2. Slot assignment as a pure function

`src/ash_captions/styles/render_free.py`, tested before anything renders.

```python
def assign_slots(words: Sequence[Word], slots: Sequence[Slot]) -> tuple[int, ...]
```

Returns, per word, the index of the slot it takes. Deterministic: the
same phrase always lays out the same way.

1. **Classify.** A word is a *connector* when its normalised form (lower
   case, surrounding punctuation stripped) is in `CONNECTOR_WORDS` — the
   closed class of articles, prepositions, conjunctions, pronouns and
   auxiliaries ("the", "on", "a", "and", "in", "of", "to", "is", ...).
   Everything else is *content*. A token containing a digit is always
   content, whatever it looks like: "2nd" is the word the big-number look
   exists for.
2. **Rank the slots.** Use `slots[:n]` for an n-word card — declaration
   order is the look author's reading order — sorted by `scale`
   descending, ties broken by declaration index. Stable, no float
   equality trouble.
3. **Fill.** Content words in their original order take the most
   prominent slots; connectors, in their original order, take what is
   left. So for `["the", "2nd", "Highest", "residential"]` the biggest
   slot gets "2nd", the next "Highest", the next "residential", and the
   smallest italic slot gets "the" — which is the reference frame.
4. More words than slots (impossible for a validated look, but the
   function is total) cycles: slot `i % len(slots)`.

**Test** — `tests/test_styles/test_free_slots.py`, the largest test file
of the three: the reference phrase lands where the reference frame has
it; connectors sink and content rises; digits never sink; punctuation and
case do not change the classification ("The," == "the"); ties in `scale`
resolve by declaration order; a card shorter than the slot list uses the
first n slots; an all-connector and an all-content card are both total;
calling twice gives the same answer; more words than slots cycles;
the empty card is `()`.

### 3. The renderer

New `src/ash_captions/styles/render_free.py` with `free_events(...)`,
plus **one branch** in `styles/render.py:_card_events`:

```python
if style.layout.mode == "free":
    base = _anchor_xy(style, width, height, None)
    moved = _anchor_xy(style, width, height, anchor)
    return free_events(card, style, base_name, width, height,
                       offset=(moved[0] - base[0], moved[1] - base[1]))
```

The offset is computed in `render.py` so `render_free.py` never imports
back from `render.py` — no import cycle, and the Studio's existing drag
handle keeps working on a free look by moving the whole cluster.

Per word, one event, `start = word.start`, `end = card.end`:

```
{\an5\pos(X,Y)\fn<font>\i<0|1>\c<role colour>\fscx<S>\fscy<S><entrance>}WORD
```

- `\an5` so `\pos` is the word's centre and `x`/`y` mean the same thing
  regardless of the look's `align`.
- `X = (slot.x * width) + offset_x`, `Y = (slot.y * height) + offset_y`.
- `S = round(slot.scale * 100)`; the look's `size` stays on the Style
  line, so one look scales correctly at any PlayRes.
- colour from `getattr(style.colors, slot.role)` through
  `ass_inline_colour`.
- text through the existing `_prepare_word_text` (uppercase + the
  fullwidth-lookalike escaping), imported from `render.py`… no: copied as
  a two-line local helper is not acceptable duplication, so `render.py`
  keeps ownership and `render_free` receives already-prepared text? No —
  `render_free` imports `_prepare_word_text` lazily inside the function,
  the same deferred-import idiom the codebase already uses for
  `config.app_root`. **Decision: `free_events` takes the prepared text
  from a small local `_prepare` that calls `str.upper` and the shared
  `_ESCAPE_MAP`, both imported from `render.py` at module level — safe,
  because `render.py` imports `render_free` lazily inside `_card_events`,
  so neither module is half-initialised.**

### 4. The two entrances

Measured off the owner's frames, per the spec:

- **stretch-collapse** — enters ~180 % wide, snaps to 100 % over ~120 ms,
  fading in: `\fscx{1.8·S}\fscy{S}\t(0,120,\fscx{S})` + the `\fad`.
- **fade-settle** — fades in over ~240 ms while shrinking from ~110 % and
  dropping a few pixels: `\fscx{1.1·S}\fscy{1.1·S}\t(0,240,\fscx{S}\fscy{S})`
  + `\move(X, Y-10, X, Y, 0, 240)` + the `\fad`.

`\pos` and `\move` do not compose in libass (the same trap `render.py`
documents), so fade-settle emits `\move` **instead of** `\pos`.

The look's own `exit` transition still applies: every word of a card ends
at the same moment, so entrance and exit merge into one
`\fad(entrance_ms, exit_ms)` — two `\fad` tags on one line do not
compose either. Both halves are clamped to the event's own length.

**Test** — `tests/test_styles/test_render_free.py`: one event per word;
every event ends at `card.end` (that is the accumulation); `\pos` present
for stretch-collapse and absent for fade-settle, which carries `\move`
ending at the slot point; the scale, colour, font and italic tags each
carry the slot's value; the `\t` timings are 120 and 240 ms; the merged
`\fad`; the anchor offset shifts every slot by the same delta; a
`WordStyle`-shaped `x`/`y` override replaces the slot position; a
`mode: "line"` style never reaches `free_events`.

### 5. Word position override

A word may override its own position through `WordStyle.x` / `WordStyle.y`
(fractions of the frame). `WordStyle` is **track B's** addition to
`styles/schema.py` and does not exist in this worktree, so
`free_events` takes an optional
`word_styles: Mapping[tuple[float, float], _Placement] | None` keyed by
`(word.start, word.end)` — the interface the spec fixes — and reads only
`.x` and `.y` off it, through a local `typing.Protocol`. No import from
`app`, no duplicate `WordStyle` dataclass for the integrator to reconcile.
My own tests pass a small local stub. `render.py`'s branch does not pass
`word_styles` yet, because `_card_events` has no such parameter until
track B lands; adding it is a one-argument change for the integrator, and
this is called out in the report.

### 7. Verify by rendering

`tests/test_styles/test_free_real.py`, following
`tests/test_styles/test_glow_real.py` exactly: skipped unless
`ASH_REAL_FFMPEG` is set, burns real frames with the bundled ffmpeg onto
a flat grey `lavfi` frame with `fontsdir` pointed at the bundled fonts,
and **measures pixels**:

1. **Four treatments in one caption.** Burn REEL ESTATE's four-word card,
   take the frame near the card's end, and find each word's glyph
   bounding box by masking on its slot's colour. Assert: four disjoint
   boxes; the big yellow word's box is at least twice the height of the
   small italic ones; each box's centre is within tolerance of its slot's
   `(x·width, y·height)`.
2. **Words accumulate.** A frame taken just after the first word's start
   has one cluster of ink; a frame near the card's end has four. This is
   the behaviour a per-word `end` would destroy.
3. **The entrance animates.** Two frames of the stretch-collapse slot,
   one ~40 ms in and one ~300 ms in: the early bounding box is
   measurably wider than the settled one, at the same height.
4. **The colour landed.** Sample inside the big word's box and assert the
   pixel is the look's `active` colour, not the look's `text` colour.

## Revisions while implementing

Recorded here rather than silently.

1. **`Slot.font`.** The spec's slot fields are position, size, colour role
   and italic. The reference frame uses *two faces*, so an optional
   per-slot `font` was added, validated against the bundled manifest by
   exactly the rule `Style.font` uses. It cost `Layout.from_dict` a
   keyword-only `check_font`, threaded from `Style.from_dict`.

2. **`\bord`, found by rendering.** libass does not scale the border with
   `\fscx`/`\fscy` -- it is a Style-line property in outline units. Burned
   at size 200, every slot came out with the same 11 px border whatever
   its scale, so a 0.5x word wore an outline twice as heavy, relatively,
   as a normal caption's, and looked like a sticker. Free events now emit
   `\bord` scaled by the slot. Nothing in the plan predicted this.

3. **The looks were three times too small on the first burn.** The first
   REEL ESTATE had size 92 and a 1.7x slot: the "big" word measured
   127x77 px on a 1080x1920 frame, nothing like the reference. Base sizes
   went to 140-160 with slot scales up to 2.85, measured back to
   ~193 px of glyph height on the big slot.

4. **`test_anchor.py`'s two shipped-style sweeps were narrowed to line
   looks.** They assert that every shipped look pins all its events to
   one anchor point. A free look puts every word at its own point on
   purpose and takes the anchor as a cluster offset, so the invariant is
   false by design for the three new looks. This is the one file outside
   the track's list that had to change, and the free behaviour it stopped
   covering is covered in `test_render_free.py`.

5. **The `shadow` colour role is legal but poor**, found while building
   the pixel fixture: setting `colors.shadow` to anything but
   `#00000000` also switches on the Shadow column for the whole look
   (`ass_format.ass_header`), so that colour lands behind every word.
   Left in `SLOT_COLOUR_ROLES` -- it names a real palette key -- and
   documented; none of the three shipped looks uses it.

6. **The pixel fixture uses four treatments in three colours**, which is
   the reference's own structure (its two small italic words are both
   white). Two words sharing a colour are separated by measuring inside a
   window around each slot.

7. **`Slot.border`, found by looking at the frame rather than measuring
   it.** REEL ESTATE's black word passed every pixel assertion and was an
   unreadable black slab: a black fill inside a black `\bord` has no
   letterforms left. Slots gained `border`, a multiplier on the look's
   outline width, and the black slot sets it to `0.0`.

8. **Figures now outrank ordinary content in `assign_slots`.** Burned
   through BIG NUMBER, "worth $4.2m in Malibu" put *worth* on the 2.85x
   slot, because "$4.2m" was merely the second content word.
   `prominence_rank` is now three tiers -- figure, content, connector --
   and the big-number look does what its name says. The reference phrase
   is unchanged by it.

9. **BIG NUMBER's biggest slot went from 2.85x to 2.30x.** At 2.85 the
   figure ran off both edges of the frame. The layout does not measure
   text, so this is a limit rather than a fix: a very long word on a very
   large slot can still overflow, and the editor drags it or the look's
   scale comes down.

10. **`Layout.intensity`**, added after the competitor note (SubKick's
    "auto-compose" carries the same dial). One number, 0.0-1.0, default
    1.0 so every shipped look is as drawn. It interpolates each slot's
    `x` toward the centre column and its `scale` toward 1.0 -- `y` is
    left alone, or the words would land on top of one another. Applied
    **after** `assign_slots`, so the dial changes how dramatic a layout
    is and never which word goes where. Rejected on a line layout, the
    same rule `slots` has.

11. **Safe zones: nothing to change, now asserted.** Measured on burned
    frames, the topmost ink of the three looks sits at 26.7% / 43.1% /
    26.7% of frame height and the bottommost at 72.0% / 64.0% / 74.3%,
    against reserved bands of the top 10% and bottom 12%. Six burn tests
    (three looks x intensity 1.0 and 0.0) now hold that, plus a cheap
    slot-centre band check for a future look author.

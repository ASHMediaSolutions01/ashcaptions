# ASH Captions v0.5 — design

Date: 2026-09-04. Status: approved in chat by Ghazi; this is the written form.
Builds on `2026-08-29-ash-captions-design.md` (the product) and the
2026-09-04 readiness scan (`docs/audits/2026-09-04-readiness-scan.md`).

## Goal

The first build the six editors install and test. v0.4.2 is correct and
installable; v0.5 closes the three things they will hit in the first hour
(captions stuck on a grid, no way to judge captions in a language they do
not speak, glow looks that hide the word) and makes the install and the
guide good enough that nobody needs help.

Six pieces, each independently shippable and testable:

1. Move captions anywhere (Studio drag, per job)
2. Caption check for languages the team does not speak
3. Glow looks rendered as a halo, not a blob
4. Installer preflight and an uninstaller
5. Queue and Studio polish, "Starting and stopping", guide screenshots, shareable guide
6. Release 0.5.0

Out of scope (later, on their own specs): 9:16 reframe, emoji/sticker
bursts, speaker names, B-roll, caption text editing.

## 1. Move captions anywhere

### Behaviour

In the Studio, the rendered caption on the video is draggable. While
dragging, a dashed outline follows the pointer; on release the `.ass` is
re-rendered with the new anchor (the existing restyle path, ~30 ms) and the
overlay reloads without touching the playhead. A **Reset position** button
appears in the header while a custom position is set; it removes the
override and re-renders. **Burn this look** and every later restyle of the
job use the same position. The position is per job, not per look: picking
another look keeps the position.

Keyboard: with the caption focused (it is a button-like element with a
label "Caption position"), arrow keys nudge by 1% of the frame, Shift+arrow
by 5%, Escape resets.

### Data

`JobOptions` gains `caption_x: float | None` and `caption_y: float | None`,
fractions of the frame width/height in [0, 1], both set or both `None`.
Stored with the job like every other option (SQLite JSON column, Pydantic
model, dataclass). Fractions, not pixels, so the same value is right at
1080x1920 and 1920x1080 and survives a restyle that changes `PlayRes`.

### Engine

`render_ass(cards, style, *, play_res, anchor=None)` where `anchor` is the
absolute anchor point in `PlayRes` pixels. When set:

- every event carries `\pos(x,y)` (static) or `\move(...)` whose end point
  is the anchor (rise/slide entrances), instead of relying on the Style
  line's margins;
- the numpad `\an` code is unchanged, so a left-aligned look stays
  left-aligned around the new anchor; the anchor is the same point
  `_anchor_xy` returns today, only moved.

`_anchor_xy(style, width, height, override=None)` is the single place that
turns fractions into pixels: `(caption_x * width, caption_y * height)`.

### API

`POST /api/jobs/{id}/restyle` body gains optional `caption_x`, `caption_y`
(both or neither; each in [0, 1]; validated at the boundary). Omitted means
"keep the job's current position"; explicit `null` for both clears it.
`POST /api/jobs/{id}/burn` reads the stored position. `GET /api/jobs/{id}`
already returns options, so the page knows whether a position is set.

### Studio

The JASSUB canvas sits over the `<video>`. A transparent drag layer over
the caption's bounding box (from the current card's anchor and the look's
position row: bottom/centre/top/lower third) captures pointer events.
Dragging moves a dashed rectangle; release converts the pointer position
to fractions of the video's rendered box (accounting for letterboxing) and
calls restyle. During a drag the overlay is not re-rendered (one restyle
per release, not per mousemove).

### Tests

- render: with `anchor`, every Dialogue line contains `\pos(` or `\move(`
  ending at the anchor; without it, output is byte-identical to today.
- fractions to pixels for portrait and landscape play_res.
- API: rejects one coordinate without the other and values outside [0, 1];
  restyle stores the position; burn-only job carries it into the burn.
- Real: restyle the Spanish interview to `caption_x=0.5, caption_y=0.25`,
  burn, extract a frame with ffmpeg, and check the caption sits in the top
  quarter (pixel row of non-video-coloured text).

## 2. Caption check for languages the team does not speak

### Behaviour

The Studio's transcript panel becomes a two-line list (source line, then
English line when available) instead of a one-line horizontal scroller. It
stays synced to the playhead. Two additions:

- **Uncertain words.** Words whose transcription confidence is below 0.5
  are underlined amber; below 0.3, red. A header chip reads
  "12 uncertain words" and clicking it jumps to the next one (and seeks the
  video there). Confidence is the `p` the transcript already stores per
  word; nothing new is computed.
- **Show English.** A toggle in the transcript header. When the job was
  translated (`en_words` in the saved transcript), the English line under
  each card comes from those words, aligned by time. When it was not, the
  toggle is replaced by a **Translate to check** button that runs only the
  translation pass from the saved transcript (no re-transcription), writes
  `.en.srt` and `en_words`, then shows the lines. Progress uses the
  existing job progress stream; the button is disabled while running.

No caption text editing. The check tells the editor *where to look*; the
fix remains the client glossary or a re-run.

### Data and API

`GET /api/jobs/{id}/transcript` returns `{language, words:[{w,s,e,p}],
en_words:[{w,s,e}] | null}` read from the saved transcript (new route; the
raw file is already beside the outputs). `POST /api/jobs/{id}/translate`
enqueues a translate-only job (a new `JobKind` alongside burn-only; the
runner's existing translate step, reading the saved transcript). Both need
the `X-ASH-Client` header like every other mutating route.

### Tests

- transcript route shape; 404 without a saved transcript.
- translate-only job: never calls the transcriber, writes `.en.srt`, and
  the saved transcript gains `en_words`.
- Studio: with a fixture transcript, the panel marks the right words and
  the chip count matches; Show English renders the aligned lines.
- Real: run "Translate to check" on the Spanish interview through the
  installed exe; the panel shows English under Spanish.

## 3. Glow as a halo

Today the `glow` active-word effect widens the outline in the active
colour and blurs it, so the word's own fill and its halo are one colour
and the letterforms vanish. New rendering: the glowing word is emitted
twice. Layer 0 carries the halo: the same text with every other word fully
transparent, the active word with transparent fill, a wide outline in the
active colour, `\blur` and `\be`. Layer 1 carries the crisp text exactly as
the `pop` effect renders it (active colour fill, the style's own outline).
libass draws layer 0 under layer 1, so the halo sits behind a readable
word. No style JSON changes; GLOW MINT, NEON GLOW and OCEAN pick it up.

Tests: the glow branch emits two Dialogue lines per card with layers 0 and
1; the layer-1 line has no `\blur`; the real-libass suite renders GLOW
MINT and checks the active word's centre pixels are the text colour, not
the glow colour. Visual: preview frames of the three looks on the reel,
compared to the 0.4.2 frames kept in the scan folder.

## 4. Installer preflight and an uninstaller

`install.ps1` gains a preflight block before anything is downloaded:

- 64-bit Windows, or stop with "ASH Captions needs 64-bit Windows".
- Windows build 17763 or newer, or a warning.
- 4 GB free on the install drive, or stop with the number.
- TLS 1.2 enabled for the download.
- Long paths: warn if `LongPathsEnabled` is off (needs admin to change).
- Download failures say what to try: "check the internet connection; if
  this PC uses a proxy, ask Ghazi", instead of a raw .NET exception.

`installer/uninstall.ps1` and `Uninstall-AshCaptions.bat`: quit the running
app, remove the logon task or Startup shortcut, the Desktop and Start Menu
shortcuts, and the install folder. `C:\AshCaptions` (the editors' output)
is kept unless `-RemoveData` is passed, and the script says so.

`-CheckOnly` runs the preflight and reports without installing. Tests:
the preflight block is exercised with `pwsh`-free unit checks where
possible (parse the script, assert the checks exist) and by a real run of
`-CheckOnly` and of the uninstaller against a scratch install.

## 5. Polish, "Starting and stopping", guide

Queue: one primary button per row (**Open in Studio**), the rest as small
secondary actions; a finished job shows the status pill and the time, not a
full green bar; the disabled Start button reads as disabled without being
invisible. Studio: the video shows the job thumbnail as its poster so a
clip that opens on white does not look broken.

Guide (`/guide` and `docs/EDITOR-GUIDE.md`): a "Starting and stopping"
section (logon task, Desktop and Start Menu shortcuts, the tray menu, Quit,
what to do if the tray icon is missing), "Moving a caption", "Checking
captions in a language you do not speak", the uninstaller, and new
screenshots for every figure taken from the 0.5 build. A standalone
`docs/ASH-Captions-Guide.html` with the screenshots embedded (data URIs)
so it can be sent to the team before they install.

## 6. Release 0.5.0

Version bump, full suite, build, the real-bundle checks from 0.4.2
(installer from the public release, logon-style launch, update relaunch via
a local manifest, the job rehearsal with the rotated reel), publish with
`scripts/release.py`, tag `v0.5.0`, push, STATUS updated. The 0.4.2 install
at `Temp\ashinst4` (made by the real download) must update itself to 0.5.0
through the tray, which is the first real update across published
versions.

need. Integration (merge order C, A, B, D, E), the version bump, the build
and the release are done by the lead on master.
